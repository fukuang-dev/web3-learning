# 练习 01：交易观察器

## 目的与运行

先通过离线字段认识区块、交易和回执。数据全部虚构；本练习不进行网络请求，不连接钱包，不签名、不发送交易，不需要密钥。

环境：Node.js 22+（本机实际验证 v24.14.1），零第三方依赖。
在仓库根目录执行：

```sh
node 01-blockchain-basics/exercises/01-transaction-inspector/demo.mjs
```

文件职责：`sample-data.mjs` 提供字段样本；`analyze-transaction.mjs` 演示回执观察；`demo.mjs` 输出三个场景。

## 预期与实际结果

2026-11-02 导师在本机运行通过：高度 `100`，交易数 `1`；成功回执 `succeeded / 3n`；失败回执 `reverted / 3n`；无回执 `receipt-unavailable / 0n`。`n` 是 BigInt 的显示后缀。
另行断言通过：未知 status 返回 unknown、错配哈希和链头落后会报错、同高确认数为 1。这些检查仅验证教学函数，不是支付系统安全测试或学习者能力验收。

## 独立作业（不提供完整答案）

在本目录自行创建以下文件：

1. `inspect-block.mjs`：导入 sample-data，输出十进制高度、区块哈希、父区块哈希和交易数；验证样本交易哈希在区块交易列表中。支持 `transactions` 是空数组的场景。无需实现 RPC 或加装依赖。
2. `answers.md`：用自己的话解释区块与交易；对成功、失败、无回执三个场景，分别写出前端可以显示什么、还不能得出什么业务结论。记录实际命令、输出、耗时和不理解的地方。

不得直接把导师 demo 视为自己已完成的作业。完成后在聊天中说明文件已保存，导师会读取本地代码审查。

## 知识测试

1. 前端已经拿到交易哈希，为什么订单还不能直接变成已支付？
2. 为什么两个不同的区块可能有相同高度，但哈希不同？
3. RPC 暂时返回 null 回执，你能确定交易正在等待打包吗？还需要排查什么？

## 验收标准

- 脚本实际运行，字段和十六进制转换正确，空交易区块不崩溃。
- 能独立解释三种观察结果；不把交易执行成功等同于商户到账。
- 三道问题有自己的论述，经审查和追问通过。
- 将个人理解及实际耗时追加到日志，导师依据证据更新 PROGRESS。

## 当前范围限制

演示把「回执区块仍在规范链」作为前提；仅用 head 和区块号计算的是观察到的确认次数，未检测重组和最终性。业务支付判断还须核验链、支付合约、事件、订单、代币、收款方、金额及确认策略，后续支付网关阶段实现。
