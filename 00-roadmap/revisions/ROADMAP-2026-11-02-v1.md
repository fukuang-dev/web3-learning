# 12 周学习路线

起点：金融行业前端工程师；每天 1～2 小时。周数代表建议学习节奏，不按日历强制推进。
当前仅展开第 1 天，后续教程在达到前置标准后创建。

| 阶段 / 周数 | 核心内容 | 实战 | 阶段验收门槛 |
| --- | --- | --- | --- |
| 1 / 第 1～2 周 | 区块与交易、密钥与地址、钱包及签名、Gas、EVM、合约、ERC-20、Ethereum 与 L2 | 浏览器分析真实测试交易；viem 读区块/交易；复述签名到上链流程 | 能独立解释一笔测试交易及回执，区分提交、执行与确认 |
| 2 / 第 3～4 周 | Solidity 类型、可见性、view/pure/payable、modifier、mapping/struct/array、event/error/require、继承、interface/library、OpenZeppelin | 计数器、资金管理、ERC-20；转账、授权、transferFrom、事件 | 独立完成简单合约，解释权限和资金流 |
| 3 / 第 5～6 周 | Forge/Cast/Anvil、编译部署调试、单测、fuzz、invariant、重入、权限、精度、Oracle 风险、CEI | ERC-20 完整测试、本地部署、漏洞复现与修复 | 关键路径与边界测试通过，修复经测试验证 |
| 4 / 第 7～8 周 | wagmi/viem、RPC、连接钱包、链 ID、读写合约、签名、交易和事件监听 | React DApp：地址、余额、转账、授权、状态反馈 | 在测试链完整操作，正确处理拒签、错误链和失败交易 |
| 5 / 第 9～12 周 | React/TS/Vite + Solidity/Foundry + Node.js/TS/数据库/链上同步 | Web3 Merchant Payment Gateway | 逐个通过以下里程碑，形成 GitHub 作品集 |

## 支付网关里程碑（现在仅定义门槛）

| 里程碑 | 交付范围 | 验收要求 |
| --- | --- | --- |
| M1 / 第 9 周 | 订单模型、唯一订单号、金额/代币/链/商户绑定、状态机、超时策略、支付合约设计 | 金额用整数最小单位；支付参数防篡改；明确资金归属及超时与迟到支付规则；设计审查通过 |
| M2 / 第 10 周 | 合约、测试 ERC-20、钱包连接、授权、付款 | 合约检查订单、金额、代币、收款方；重付与越权用例失败；测试通过；资金流可追踪 |
| M3 / 第 11 周 | 后端持久化、链上事件同步、确认数、区块重组、重试与补扫 | 事件按 chainId/txHash/logIndex 幂等并处理重组；重复处理不重复入账；宕机恢复能补齐数据 |
| M4 / 第 12 周 | 商户交易记录、订单查询、交易哈希与浏览器链接、联调与文档 | 成功、失败、超时、重复支付、重组路径演示与测试；可复现部署；测试网演示和 GitHub README |

必须验收当前里程碑，再进入下一个。交易执行成功还需要事件与订单语义校验，才可判定支付满足业务条件。

## 长期阅读方向

Coinbase 钱包/支付、Chainlink 预言机/跨链、Circle USDC、Uniswap 合约与前端。到对应阶段再选择官方源码和文档，记录模块职责、调用链、测试和安全边界；这些生态不是唯一求职目标。

## 每次教学结束

追加 LEARNING-LOG；更新 PROGRESS；完善已有专题和 KNOWLEDGE-MAP；有实际问题时追加 ERROR-BOOK。阶段通过后才创建 PHASE-XX-SUMMARY，不能预填完成结果。
